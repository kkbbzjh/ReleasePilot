# ReleasePilot

Windows 桌面 GitHub 软件更新管理器。

## 当前功能 · v0.3.0

- 添加 GitHub 仓库订阅
- 关联本地 EXE 并读取文件版本
- 获取最新正式版 Release 和更新日志
- 将订阅保存在本机 SQLite 中
- 在 GitHub Actions 上构建 Windows x64 单文件程序
- 下载并启动 EXE / MSI 安装向导
- ZIP / 7z 解压更新、配置保留与无备份覆盖
- 单文件 EXE 替换与 ReleasePilot 自更新
- 手动确认版本对应关系，按已安装的 Release 追踪配置包
- 解压时显示文件名、文件数量、解压大小、进度与耗时
- 主窗口、更新设置、下拉菜单、右键菜单、确认和错误弹窗共用一套主题

下载最新版本：[Releases](https://github.com/kkbbzjh/ReleasePilot/releases/latest)。Windows x64，单文件版无需另装 .NET。

应用内的按钮、输入框、复选框、滚动条与进度条统一配色、圆角、间距和交互状态。确认操作默认聚焦取消，关闭确认窗口不会执行操作。文件/文件夹选择器使用 Windows 原生界面，第三方安装向导由对应软件提供。

## 开发

Windows + .NET 10 SDK：`dotnet restore`、`dotnet run`。

版本比较回归检查：`dotnet run --project tests/VersionHelper.Tests/VersionHelper.Tests.csproj -c Release`。Windows 下可追加 `-- <EXE 路径> <Release 标签>`，验证实际发布文件的版本。

版本比较支持 `v` 前缀、末尾补零（`0.2.0` 与 `0.2.0.0`）、构建元数据（`0.2.0+提交号`）以及预发布版本。无法解析的日期、提交号或自定义标签显示“需要确认”，可在核实本地已安装最新 Release 后使用“标记为已安装此版本”，也可“清除安装标记”。EXE 确认绑定文件内容，文件变化后会重新提示。

## 安装与更新

选择订阅后，点击“安装 / 更新”，选择 Release 附件与更新方式。每次执行前都会显示附件、版本和目标位置供核对：

- **修复或重新安装**：勾选“重新安装此版本（修复损坏文件）”，会重新下载所选 Release 的附件，版本相同也可安装、解压或替换。已识别为同一已安装版本时默认勾选。此操作仍遵守保留路径设置，不会清空整个目录。
- **标记为已安装此版本**：只适用于你已经手动安装好软件、需要登记 Release 对应关系时；不会下载、安装或修复文件。“清除安装标记”仅移除版本记录，不会卸载软件。
- **选择系统与架构**：按附件文件名标注 Windows、Linux、macOS 等及 x64、x86、ARM64 等架构，优先排列和选择匹配当前 Windows 系统架构的附件。Windows x64 的 x86 应用标为兼容，驱动和插件仍需核对宿主。未标明或标记冲突的附件不自动选中；之前明确选过的适用附件可沿用。可展开其他系统、架构及格式，其他系统和未支持格式不能在当前更新器中应用。架构不匹配的附件不默认选中，需要额外勾选兼容性确认后才能手动使用。

平台与架构判断是基于文件名的提示，不是对包内所有文件或软件运行条件的保证；请核对发布说明。配置包等无平台标记的附件可在手动选择后更新。


- **EXE / MSI 安装包**：下载后打开正常安装向导。安装器退出后，用户确认安装成功并选择安装后的主程序，才记录版本；不会把下载完成或启动安装器当作安装成功。
- **ZIP / 7z 压缩包**：使用“关联目录”选择软件或配置包目录，先解压到临时目录，再直接覆盖同名文件（不创建备份），不删除包中未包含的本地文件。可填写不覆盖的相对路径（分号分隔，如 `mpv.conf;input.conf;portable_config/mpv.conf`）；可选择去掉唯一顶层目录。配置包根据成功更新或手动确认的 Release 记录追踪版本，不使用播放器 EXE 版本，也不逐个监控配置文件变化。
- **单文件 EXE**：使用“关联 EXE”选择本地主程序，直接替换，不创建备份。请先关闭目标程序；文件夹更新中途失败可能部分完成，请关闭目标程序后重试。ReleasePilot 自身由独立助手在退出后替换并重启。

例如 `dyphire/mpv-config` 的 7z 整合包，应选择整合包解压目录；单独配置包则选择实际配置目录，并根据包内目录结构决定是否去掉顶层目录。自定义配置应加入保留列表。

不再创建旧文件备份。ZIP / 7z 和单文件更新结束后清理临时文件；安装器可能启动子进程，因此其临时文件保留。历史备份与临时文件可通过“后台与通知 → 打开临时 / 历史更新目录”找到并手动清理。附件提供 GitHub SHA256 摘要时会核验，大小或摘要不匹配时停止更新。旧订阅数据库会自动增加所需字段，保留原有订阅。

### 解压时间较长时

更新窗口会显示当前文件、已完成文件数、已解压 MB、字节进度和累计耗时。读取压缩包目录或准备解压器时先显示等待动画；已知解压总大小后显示实际字节进度。7z 固实压缩包可能在同一文件或准备阶段停留较久，耗时仍会刷新；一段时间没有新的解压数据时会提示可继续等待或取消，不会仅因耗时较长就判定失败。点击“取消解压”后需等待当前读取结束，此阶段尚未覆盖目标目录。

## 自动构建

推送 `v*` 标签后执行 `.github/workflows/release.yml`，并发布带版本号的 EXE（如 `ReleasePilot-v0.2.0.exe`）和 `SHA256SUMS.txt`，校验文件使用相同的 EXE 文件名。标签构建使用标签版本，`main` 分支和手动构建使用项目文件中的 `Version`。也可在 Actions 手动运行工作流，只生成可下载构建附件。

## 后台检测与通知

后台检测已支持：主界面“后台与通知”中开启后，关闭窗口会继续在 Windows 托盘运行，可选择登录后启动和 5–1440 分钟的检查间隔。同一新版本只提醒一次，点击提醒打开软件后自行安装；右键托盘可检查、设置或退出。默认关闭，不会自动安装更新。系统勿扰模式可能隐藏提醒。

> 部分软件的 EXE 文件版本与 GitHub 标签不同，无法安全比较时会显示“需要确认”。
